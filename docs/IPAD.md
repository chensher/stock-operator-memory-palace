# iPad 交互调整

- 沿用实际三维物件触碰，不增加剧情选项或跳幕面板。
- 演出结尾恢复触屏方向键，支持一指走动、一指环顾；进入演出或账册时隐藏方向键。
- 账册轻点左右页、左划往后、右划往前。竖直拖动不会误翻；抬手才确认翻页，中断手势不会确认。原1901年演出与其余章节行为一致。
- 账册底部有无边框的前后翻页、换册、放回操作，避免需要实体键盘。
- 所有主要触屏按钮至少44像素高；方向键52像素，账册操作48像素。
- 字幕、按钮与页边距考虑安全区，横竖屏自动调整。没有禁止浏览器整体缩放；仅三维操作区域阻止滚动和长按选中文字。
- 单个场景手势只有一个指针所有者，第二根手指不会夺走操作。转屏、离开页面、失去触碰捕获会清理操作状态。
- 触屏演出直接绘制三维场景，不创建泛光、调色等多层离屏缓冲，不启用实时阴影。像素倍率不超过1，实际画布预算约110万像素，较大屏幕进一步降低倍率。
- 静态建筑、地板、书架等按材质合并，保留可操作物件和动画部件的独立变换。房子在平板上只启用最近的两盏点光源。
- 进入事件先显示可取消的过渡，再创建场景；创建或绘制失败会回收事件并提供重试、返回、文字阅读。图形上下文丢失时停止反复绘制，恢复后可重进。

自动验证包括多指干扰、捕获丢失、中断与弹窗取消；两种演出引擎的账册手势；768×1024、1024×768、820×1180、1180×820的纸张边界、翻页、换册和放回。浏览器预览检查触屏媒体条件及横竖屏布局。**尚未在实体 iPad Safari 上实测**，不将桌面尺寸模拟等同于真机验证。

中断处理参考 [MDN pointercancel](https://developer.mozilla.org/en-US/docs/Web/API/Element/pointercancel_event)。

追加验证：模拟真实 WebGL 上下文丢失，确认文字阅读可用；恢复上下文后，确认重进成功。自动检查场景创建失败的回滚、快速重复进入的取消、合并几何的位置与交互保留、平板画布预算。仍未将桌面浏览器触屏模拟视为实体 iPad Safari 实测。

绘制开销的依据见 [Three.js 后处理](https://threejs.org/manual/pages/post-processing.html)；图形恢复机制见 [MDN webglcontextlost](https://developer.mozilla.org/en-US/docs/Web/API/HTMLCanvasElement/webglcontextlost_event)。

## 第二、三章的追加排查（2026-10-02）

用户反馈两章出现通用进入失败提示。尚未取得该 iPad 的具体异常与系统版本，因此不能断言其根因或声称已在真机修复。

- 修正了画布资源的实际生命周期：Texture.dispose() 只释放图形纹理；页面替换、事件退出及失败退出现在也将旧的二维画布缩到1×1。移动端直接分配最终尺寸，纸面1024×1447改为512×724，面积约为原来的四分之一，不创建全尺寸中间画布。关闭移动端画布纹理的自动细节层。
- 清理持久相机上的旧手部模型、关闭场景的根节点和车站引用，避免反复进入或换段后继续持有旧对象。
- 第二章电报段落改为拿起并递送纸面指令，电报器留在桌上。其他非纸物件按大小缩放并保持正常姿态，避免挡住递送目标；账册仍使用正常阅读姿态。
- 失败提示新增折叠的“查看错误详情”，包括事件、演出阶段、具体异常、版本与浏览器标识。仅在本页显示，不上传。画布创建失败有明确原因说明，不再只得到空引用错误。
- tests/canvas-memory.mjs 验证预算、主动释放、空上下文、重复进入及第二章递送。原有全书、纸张方向、触屏、中断和来源覆盖检查均通过。
- 在电脑浏览器的触屏模式、1024×768下，tests/gpu-chapters.html 使用实际 WebGL 完成第二章三个子事件和第三章全部流程、账册与交替重进，共1896次实际绘制；关闭事件后几何和纹理计数回到基线。此测试加速故事时钟，验证实际图形资源与流程，不证明正常播放节奏或真实 iPad Safari 兼容性。
- 实际应用中模拟一次二维画布创建失败，确认错误详情可读，随后重新进入第三章成功。

画布分配与释放的排查参考 [WebKit 画布内存问题记录](https://bugs.webkit.org/show_bug.cgi?id=195325)。该历史记录不意味着所有现行 iPadOS 都具有同样故障；本设备的具体原因仍需要错误详情来确认。
