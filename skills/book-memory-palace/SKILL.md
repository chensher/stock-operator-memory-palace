# 书籍的沉浸式记忆宫殿

将书籍变成可以亲自走进去的叙事空间。这里的“记忆宫殿”指承载内容的空间，不意味着制作记忆游戏。默认中文原创改编，使用这份 skill 时仍优先执行当前用户的具体要求。

## 先理解书，再设计体验

1. 检查已有工程、原文、交接记录及用户反馈，延续已经认可的方向。
2. 获取完整原文。优先使用用户提供的文件；需要下载时选择可合法获取的版本。记录版本、完整性及来源，保存到项目资料中。已有完整文本就直接利用。
3. 阅读全书，梳理事件发生顺序、人物动机、条件变化、行为、结果和事后认识。针对每个子事件建立原文定位与信息清单，避免仅根据书名、章节摘要或通用主题编造演出。
4. 区分原文事实、叙述者推断与改编添加的连接。核对重要数量、日期、人物关系、因果与观点变化。不能把后来的认识提前塞给尚未经历事件的人。
5. 为每个子事件安排独立的地点、物件、动作和可见后果。房间数、章节数与事件数量由新书决定，不照搬上一项目。
6. 先做一段具有代表性的完整样片，验证叙事、物件交互与动画效果。用户认可后再扩展全书；延续已认可的效果，避免铺量时退回统一读书场景。

## 必须保留的体验要求

- 允许自由探索，提供明确但自然的环境引导。核心剧情通过直接触碰、拿起、翻开、拖动、拉动、递送、转动、走近或等待来推进。
- 参考《伊迪芬奇的记忆》的环境叙事和事件变化方式，不复刻其具体场景或资产。不同子事件应有不同的视觉构图、操作意义与演出节奏。
- 不加入记忆测验、背诵、答题、评分、排行榜、记忆训练或强制解锁。
- 不用带框选项、文字卡片列表、“选择下一幕”等界面替代戏内行动。目录、设置和退出可以在故事之外提供；演出内部的引导尽量属于场景本身。
- 追求连贯的电影感：人物、机器、物件、镜头、光线及环境变化共同表现过程。静态插画抖动、简单平移或缩放不能冒充动画 CG。插画可用于实际画框或辅助资料。
- 交互必须具有叙事意义。例如订单的递送表现执行延迟，拉动纸带体现信息滞后。避免让所有事件都只翻一张纸，或为了互动而添加无意义动作。
- 保留自然可用的暂停、退出、返回、重进机制。出错或加载中仍应能离开，不能把用户锁在画面里。

## 文本与原文信息量

- 使用大量生动、详尽、连贯的文本，不将整本书压缩成几条格言。保留事件背景、具体过程、数字、反转、失败原因以及认识如何形成。
- 文本可以沿镜头和场景逐步出现，也可以借助黑板、票据、信件、账册和环境文字分层传递。每段给足阅读时间，必要时可暂停。
- 可以学习《神探夏洛克》的信息密度：将数字、时间、关系和因果叠加在正在发生的画面中。确保主次清楚、文字可读；不要同时堆满整屏。
- 正文应像人物正在经历或回忆事件。“原文第几章”“来源说明”“此处展示原书内容”等制作说明不要反复进入戏内旁白、字幕或物件。
- 将出处、版本、改编说明放在可选的资料页或项目文档里。来源核对仍需认真完成，只是不打断剧情。
- 在场景内保留可翻阅的详尽记述，补足演出承载不下的细节；原文可作为另一册资料。翻纸两面、旋转后的文字必须保持正确阅读方向。
- 保持覆盖清单，逐事件检查信息是否遗漏。完整英文资料不等于完整中文演出；交付时如实说明哪些内容已演出、哪些保存在账册、哪些尚未改编。

## 动画、声音与操作

- 使用连续的三维运动与平滑镜头衔接。纸张递送、机械活动、人物反应和场景转场必须呈现过程，避免瞬移、突然翻倒或镜头穿模。
- 被拿起的物件应按实际大小与镜头距离安排姿态，不能放大到遮住递送目标。非纸物件不能机械套用翻纸的姿态。
- 拖动、点击与滑动阈值要清楚；多指操作不能抢走正在进行的手势。指针取消、失焦、旋转屏幕、暂停或弹出菜单时清理输入状态。
- 声音是可选增强。适量人声、环境声或音乐有帮助，但不强求。若加入，尊重浏览器首次操作后的播放限制；播放状态和开关应反映真实声音，不能仅显示“已开”。
- 默认以当前用户指定的平台为目标。需要 iPad 时，核心动作、移动、翻页、返回都应能通过触屏完成，不依赖键盘。

## 验证与故障排查

1. 验证真实入口、物件命中、动作推进、完整演出、转场、暂停、退出、重进和跨章节切换，而不只确认页面打开。
2. 用实际浏览器渲染测试材质、纹理和动画。状态机的模拟测试不能代替实际图形渲染；调整视口或开启触屏模拟不能声称已在真实 iPad / Safari 验证。
3. 设备报错时先保留具体异常、章节和演出阶段，区分程序错误、图形上下文丢失、加载失败与资源压力。不要反复将所有故障归因于设备性能。
4. 降低移动设备的像素、阴影、后期和纹理开销；缓存或合并静态资源时，保留可交互、可动画对象的身份。关闭、切换及失败退出都需要正确释放资源。
5. 检查纸张正反面、竖横屏可读性、触屏命中范围、物件遮挡和实际递送路径。错误提示应允许返回及查看具体详情；详情放在演出外，不影响正常沉浸。
6. 若用户明确允许放弃某设备适配，完成有意义的排查后可收窄支持范围。明确说明限制与验证证据，不无限投入，也不把未经验证的优化宣称为“已修复真机”。

## 交付与后续复用

- 用户需要本地快速打开时，提供可双击启动的脚本及可直接运行的构建产物，处理路径空格和重复启动。
- 用户要求发布时，完成构建、测试、仓库与站点部署，并确认公开网址可访问且确实包含当前版本。GitHub Pages 等平台的资源路径必须与部署目录匹配。
- 当前项目的发布授权只适用于当前项目。对另一本书不要默认已有公开发布、创建仓库、发送消息或使用某账号的授权。
- 简洁报告具体变化、验证结果、网址或本地入口及实质限制。避免以“电影级”“完整还原”等说法夸大已有资产或内容覆盖。
- 保存版本、事件覆盖、验证结论与未解决问题，便于断电或中断后继续。新书复用的是叙事要求和工作方法，不是固定房间、特定书中的数字或技术故障。
